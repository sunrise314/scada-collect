# 09-配置与部署

## 一、痛点引入

这一章讲部署。先说个真事。

第一次去客户工厂部署，我事先在自己电脑上跑通了，所有东西都写死：TDengine 在 `127.0.0.1`、MQTT broker 在 `127.0.0.1:1883`、用户名 `root`、密码 `taosdata`——标准的开发态默认值。我把 jar 包扔到客户服务器上 `java -jar` 启动，启动 5 秒就崩：客户的 TDengine 装在内网另一台机器 `192.168.10.23`，密码也改成了 `Scada@2024!`。

我改 `application.yaml`，重启；客户的安全员走过来：你这密码明文写在配置文件里？审计要查的。然后我又改回占位符 `${SCADA_TDENGINE_PASS:taosdata}`，让运维在 systemd 的 `EnvironmentFile` 里塞环境变量。这一来一回一个上午过去了。

更尴尬的是线程池。yudao 全局线程池默认 core=4，我以为够用，结果工厂同时 50 台 PLC、每台 4 个采集任务、每个任务 200ms——核心池直接打满，yudao 后台还有几个 Excel 导出任务在排队，整个 JVM 抖得像帕金森。

那天晚上的复盘让我把所有配置块都重写成两件事：① 任何环境相关的值都必须走占位符，② SCADA 模块要有自己独立的线程池，不跟 yudao 共用。这两个决定救了我后面好几次。

## 二、行业对比

工业 SCADA 平台的配置方式大概分三类。

第一类是 WinCC、iFIX 这种老牌 SCADA，配置全部走图形界面 + 注册表 / INI 文件，跟容器化、版本控制基本绝缘。

第二类是 ThingsBoard，全部走 YAML + 数据库混合：核心参数 YAML，业务参数（设备、规则、dashboard）全部数据库。优点是配置即数据，缺点是数据库里改一行字段没有 git 历史，二开团队很难 review。

第三类是 IoTDB 自带的配置，纯 properties 文件 + 大量硬编码常量，简洁但难扩展。

我这套走 yudao 风格——纯 YAML，按 profile 切分（`application-scada.yaml`），环境相关的值全部 `${ENV:default}` 占位符。这种设计能在 git 里 review，也能在 K8s ConfigMap 里覆盖，工业现场 systemd 装环境变量也方便。

## 三、选型与设计取舍

### 1. TDengine 走占位符不写死

```yaml
scada:
  tdengine:
    url: jdbc:TAOS-RS://${SCADA_TDENGINE_HOST:127.0.0.1}:${SCADA_TDENGINE_PORT:6041}/scada
    username: ${SCADA_TDENGINE_USER:root}
    password: ${SCADA_TDENGINE_PASS:taosdata}
```

`${ENV:default}` 语法是 Spring 标准占位符，冒号前是环境变量名、冒号后是默认值。这样配置文件本身可以放心进 git（默认值是开发态的），生产环境通过环境变量覆盖。密码不进 git、不进镜像 layer、不进配置中心，符合商用部署的安全基线。

### 2. 线程池独立 scadaCollectExecutor，不复用 yudao 全局池

这个取舍写在 `ScadaConfiguration.java` 的类注释里：

> 为什么不直接用 yudao.threadPool 全局池？因为 SCADA 的 IO 任务是阻塞型，跟 yudao 默认池里 CPU 密集型任务（excel 导出、邮件发送）放一起会互相拖慢。独立池更便于按业务限流。

阻塞型和 CPU 密集型任务混池的后果我在痛点引入里讲过。独立池还有个好处：jstack 时按 `scada-collect-` 前缀一眼能找到是哪个池的线程，方便定位问题。

### 3. 线程池参数：core=8 / max=32 / queue=200

这套参数来自一个具体场景：单台中型制造工厂典型 4-16 台 PLC，按每台 2 个并行任务算 32 已够。core=8 是稳态运行时实际并行度，max=32 是峰值保底。queue=200 配 `CallerRunsPolicy`——队列满后由调度线程自己跑任务，自然形成背压，避免内存爆掉。

这套参数的关键不是具体数字，而是**默认值就是合理值**。客户不需要调，开箱即用；如果客户现场设备超过 32 台，改 yaml 即可，不用改代码。

### 4. MySQL 表都带 tenant_id/creator/create_time/updater/update_time/deleted

这五个字段是 yudao 框架的"租户 + 审计 + 软删"三件套。所有表都带是因为：① 多租户场景下隔离基础；② 审计字段是 ISO 9001 等质量管理体系的硬要求；③ 软删避免误删数据找不回。

索引设计也按这套字段走：所有唯一约束都是 `uk_tenant_xxx`（含 `tenant_id`），保证跨租户不冲突。

### 5. 用 j2mod 不用 modbus4j

`pom.xml` 里：

```xml
<dependency>
    <groupId>com.ghgande</groupId>
    <artifactId>j2mod</artifactId>
    <version>3.2.1</version>
</dependency>
```

modbus4j 已经停更六年（最后提交 2018 年），并发场景下偶发死锁没修。j2mod 活跃维护，支持 Modbus TCP/RTU/ASCII 全三种，API 也更直白——`ModbusMaster master = new ModbusTCPMaster(ip, port); master.connect();` 一句话起连接。

### 6. OPC UA 用 Milo 不用 OpcUaClient 高级 API

`pom.xml` 引的是 `org.eclipse.milo:sdk-client:0.6.13`。Milo 的 sdk-client 给了底层 UaClient 接口，没强加高级封装；它的 `OpcUaClient` 高级 API 是另一个包，封装层太厚，订阅参数、session 超时、安全策略都被锁死。商用 SCADA 场景下，sdk-client 给的细粒度控制更值钱——能精确控制订阅 publishing interval（我们配 500ms），能调 security policy（我们默认 NONE 适配工业内网）。

## 四、关键代码精讲

### 4.1 application-scada.yaml 全景

文件：`yudao-module-scada/src/main/resources/application-scada.yaml`

整个文件按职责分了 9 块，每块都跟一个具体组件对齐：

```yaml
scada:
  # 采集总开关：false 时 ScadaCollectJob 不启动调度器，常用于灰度发布或演练停采
  collect-enabled: true
  # ReplayBuffer 本地缓存路径（RocksDB）
  replay-path: ./data/scada-replay
  # 缓存上限，100 万条约 200MB，工业现场够用
  replay-max-keys: 1000000
  thread-pool:
    core-size: 8
    max-size: 32
    queue-size: 200

  tdengine:
    url: jdbc:TAOS-RS://${SCADA_TDENGINE_HOST:127.0.0.1}:${SCADA_TDENGINE_PORT:6041}/scada
    username: ${SCADA_TDENGINE_USER:root}
    password: ${SCADA_TDENGINE_PASS:taosdata}
    driver-class-name: com.taosdata.jdbc.rs.RestfulDriver
    max-pool-size: 10
    database: scada

  modbus:
    default-port: 502
    timeout-ms: 3000

  mqtt:
    broker-url: ${SCADA_MQTT_URL:tcp://127.0.0.1:1883}
    client-id-prefix: scada-yudao-
    qos: 1
    keep-alive-interval: 60

  opcua:
    default-security-policy: NONE
    default-session-timeout: 60000
    publishing-interval: 500

  s7:
    default-rack: 0
    default-slot: 1
    timeout-ms: 3000

  sse:
    emitter-timeout-ms: 1800000   # 30 分钟
    flush-interval-ms: 1000       # 1Hz
    max-points-per-client: 500

  heartbeat:
    cutoff-seconds: 30
    scan-interval-seconds: 60

  alarm:
    auto-load-on-start: true
    retain-days: 90
```

注意几个关键点：

- **`collect-enabled: false` 是灰度开关**——上线时先关掉，让 yudao 后台、权限菜单先起来，运维确认 OK 后再开。
- **TDengine 走 RESTful Driver（`jdbc:TAOS-RS://`）**，不是原生 driver（`jdbc:TAOS://`）。RESTful 不依赖本地 .so 库，跨平台部署友好，性能略低但工业场景够用。
- **`max-pool-size: 10` 是 TDengine 的 REST 连接池上限**，跟 HikariPool 完全独立，因为 TDengine 不走 yudao 主数据源。
- **`max-points-per-client: 500` 是 SSE 单连接订阅上限**，防止单客户端吃满推送内存。
- **`cutoff-seconds: 30` 是心跳超时阈值**，超过 30s 没心跳判定断线。

### 4.2 ScadaConfiguration：线程池装配

文件：`yudao-module-scada/src/main/java/cn/iocoder/yudao/module/scada/framework/scada/config/ScadaConfiguration.java`

```java
@Configuration
@EnableConfigurationProperties(ScadaConfiguration.ScadaProperties.class)
public class ScadaConfiguration {

    @Bean(name = "scadaCollectExecutor")
    public ThreadPoolExecutor scadaCollectExecutor(ScadaProperties props) {
        ScadaProperties.ThreadPool tp = props.getThreadPool();
        ThreadPoolExecutor executor = new ThreadPoolExecutor(
                tp.getCoreSize(),
                tp.getMaxSize(),
                60, TimeUnit.SECONDS,
                new LinkedBlockingQueue<>(tp.getQueueSize()),
                r -> {
                    Thread t = new Thread(r);
                    t.setName("scada-collect-" + t.getId());
                    t.setDaemon(true);
                    return t;
                },
                new ThreadPoolExecutor.CallerRunsPolicy()
        );
        return executor;
    }

    @Data
    @ConfigurationProperties(prefix = "scada")
    public static class ScadaProperties {
        private boolean collectEnabled = true;
        private String replayPath = "./data/scada-replay";
        private int replayMaxKeys = 1_000_000;
        private final ThreadPool threadPool = new ThreadPool();

        @Data
        public static class ThreadPool {
            private int coreSize = 8;
            private int maxSize = 32;
            private int queueSize = 200;
        }
    }
}
```

几个细节：

- 线程命名前缀 `scada-collect-`，jstack 一眼能找到。
- `t.setDaemon(true)`——守护线程，JVM 退出时不需要等它，避免采集线程卡住 shutdown。
- `CallerRunsPolicy` 是关键——队列满后由调用方（也就是 `CollectTaskExecutor` 调度线程）自己执行任务，形成天然背压，调度线程被拖慢后下次扫描间隔变长，反而自我调节。
- `keepAliveTime=60s`——非核心线程空闲 60s 回收，工业现场峰值过后线程会自动回落，不会一直占内存。

注意 `ScadaProperties` 类只绑定了核心字段（`collectEnabled`/`replayPath`/`replayMaxKeys`/`threadPool`），其他配置块（`tdengine`/`modbus`/`mqtt` 等）的 Properties 类分散在各自 Driver 的包里。这是有意拆开的——每个 Driver 管自己的配置，不堆在一个大类里。商用版的 `ScadaProperties` 应该聚合所有子 Properties 字段，但我目前的实现是把 TDengine 的 Properties 放在 `TDengineConfig.java` 里、把 SSE 配置常量直接写在 `SsePushServer.java` 类里——这是个我承认的技术债，下个版本会统一收敛。

### 4.3 pom.xml 的依赖版本

文件：`scada-collect/pom.xml`

关键依赖版本：

| 依赖 | 版本 | 选型理由 |
|------|------|---------|
| `com.ghgande:j2mod` | 3.2.1 | Modbus TCP/RTU/ASCII，活跃维护 |
| `org.eclipse.milo:sdk-client` | 0.6.13 | OPC UA 底层 client，细粒度控制 |
| `org.apache.plc4x:plc4j-*` | 0.13.0 | S7 协议驱动（runtime scope） |
| `com.taosdata.jdbc:taos-jdbcdriver` | 3.3.3 | TDengine RESTful driver |
| `org.rocksdb:rocksdbjni` | 8.11.3 | ReplayBuffer 本地缓存 |
| `org.apache.commons:commons-pool2` | 跟随 spring-boot | Driver 连接池 |
| `org.springframework.integration:spring-integration-mqtt` | 跟随 spring-boot | MQTT Sparkplug B 订阅 |

PLC4X 的三个 driver（modbus/opcua/s7）都标了 `<scope>runtime</scope>`——它们只是 SPI 实现层，编译期不依赖。Milo 的 `sdk-client` 是编译期依赖，因为 OPC UA 的 UaClient 接口要直接编码用。

`rocksdbjni` 是关键依赖，给 ReplayBuffer 用。RocksDB 是单机版的，跨节点不共享，这是单实例部署的硬约束之一，下一章详细复盘。

### 4.4 scada-init.sql 的索引设计

文件：`yudao-module-scada/src/main/resources/sql/scada-init.sql`

5 张业务表（device/point/task/rule/event），索引按业务查询路径设计：

```sql
-- 设备表：租户内编码唯一、协议+启用维度过滤
UNIQUE KEY `uk_tenant_code` (`tenant_id`, `code`, `deleted`),
KEY `idx_protocol_enabled` (`protocol_type`, `enabled`),
KEY `idx_status` (`status`)

-- 任务表：启停+到期扫描的复合索引
UNIQUE KEY `uk_tenant_code` (`tenant_id`, `code`, `deleted`),
KEY `idx_enabled_due` (`enabled`, `last_run_at`),
KEY `idx_device` (`device_id`)

-- 事件表：按设备+状态查询、按触发时间排序
KEY `idx_device_state` (`device_id`, `state`),
KEY `idx_rule` (`rule_id`),
KEY `idx_state_severity` (`state`, `severity`),
KEY `idx_triggered_at` (`triggered_at`)
```

`idx_enabled_due` 是任务表的灵魂索引——`CollectTaskExecutor` 每秒扫一次 `enabled=1 AND last_run_at + interval_ms < NOW()`，复合索引让 SQL 不用回表就能拿到待执行任务 ID。

`idx_device_state` 是事件表的灵魂索引——大屏按设备过滤未确认告警，`WHERE device_id=? AND state IN (1,3)` 直接走这个复合索引，避免全表扫。

`uk_tenant_code` 都带了 `deleted` 字段，这是 yudao 软删的标准做法——软删的记录在唯一约束里依然算占用，避免同 code 误删后重建冲突。

### 4.5 README 部署文档要点

`README.md` 列了 5 步部署：

1. 准备中间件：TDengine 3.3.x 必装、MySQL 8.x 跟随 yudao 主库、MQTT broker 可选、**不需要 Redis**。
2. 配置环境变量：`SCADA_TDENGINE_HOST/USER/PASS/MQTT_URL`。
3. 引入 profile：主 `application.yaml` 加 `spring.profiles.include: scada`。
4. 初始化 MySQL 表：`mysql -uyudao -p yudao < yudao-module-scada/src/main/resources/sql/scada-init.sql`；TDengine 超表由 `PointValueServiceImpl.initSchema()` 启动时自动建。
5. maven 打包：作为 yudao 子模块加到根 pom 的 `<modules>`。

**不需要 Redis** 这一条值得讲。SCADA 状态机全内存、规则缓存全内存，没有跨节点共享需求——所以 Redis 不必要。这也决定了单实例部署是这套系统的天然边界（多活必须上 Redis 或分布式锁），下一章详细复盘。

## 五、调优与踩坑

**踩坑 1：CallerRunsPolicy 让调度线程被堵。** 有一次客户现场 50 台 PLC 全断线，重连守护狂发任务，scada-collect 池被打满，队列也堆满，`CallerRunsPolicy` 把调度线程堵死，结果正常设备的任务也被错过。这之后我加了**重连速率限制**——`DeviceConnectionManager.computeBackoffMs` 指数退避封顶 30s，避免重连风暴。

**踩坑 2：TDengine REST driver 偶发 504。** RESTful driver 走 6041 端口的 taosadapter，高并发写入偶发 504。改 `max-pool-size=10` 到 `max-pool-size=20` 缓解，根因是 taosadapter 自己的 worker 不够。生产建议把 taosadapter 的 `--restful worker threads` 调到 32 以上。

**调优：RocksDB 路径用绝对路径。** 默认 `./data/scada-replay` 是相对路径，systemd 启动时 cwd 是 `/`，实际写到 `/data/scada-replay`，跟预期不符。生产建议改成绝对路径 `/home/yudao/data/scada-replay`。

**调优：MQTT keep-alive 间隔。** `keep-alive-interval: 60` 默认值。工业现场如果 broker 走 4G，间隔建议调到 120s 减少 keepalive 报文开销；如果是内网，30s 更合理。

**踩坑 3：tdengine.database 必须先建。** 启动时如果 `scada.tdengine.database` 不存在，会报 schema 错误。`PointValueServiceImpl.initSchema()` 里有自动创建逻辑，但前提是用户有 `CREATE DATABASE` 权限。生产建议预先 `CREATE DATABASE scada;` 再启动应用。

## 六、商用化检查清单

部署前对照跑一遍：

- [ ] 所有 `${ENV}` 占位符在生产环境是否都有对应的环境变量
- [ ] `application-scada.yaml` 是否通过 `spring.profiles.include=scada` 引入
- [ ] TDengine 3.3.x 是否就绪，`scada` 库是否预建
- [ ] MySQL 5 张业务表是否都执行了 `scada-init.sql`
- [ ] `scadaCollectExecutor` 线程池参数是否按实际设备数调整
- [ ] RocksDB 路径是否改成绝对路径，磁盘剩余空间是否够 200MB×预估点位数
- [ ] systemd unit 文件是否设了 `EnvironmentFile=`
- [ ] taosadapter worker threads 是否 ≥ 32
- [ ] MQTT broker（如果用）的 ACL 是否放行了 `scada-yudao-*` client id 前缀
- [ ] 防火墙是否放行了 502/4840/102/1883/6041 五个端口
